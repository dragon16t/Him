# Celesta Glow CRM Platform - PRD

## Original Problem Statement
Clone & run the repository at https://github.com/sta-rgbj/port3.git (reference production: portal.veegal.com). ## Architecture
- **Backend**: FastAPI (Python) + MongoDB (motor) at port 8001, JWT auth, slowapi rate-limiter, optional Gemini AI, SMTP email, WebSocket notifications.
- **Frontend**: React 19 + CRA (craco) + TailwindCSS + shadcn/ui (Radix), react-router-dom v7, recharts. Port 3000.
- 16 role-specific dashboards under `frontend/src/pages/`.

### Iteration 73 (2026-02-17) — Real Root Cause: Frontend Error Handler Dumping Raw HTML
- **✅ Analysis proved production backend is UP**: 10 consecutive `POST /api/auth/login` requests to `software.celestaglow.com` returned HTTP 401 (correct backend response for wrong password). No 5xx. Cloudflare passthrough is working.
- **🐞 Real bug**: `UniversalLogin.js` error handler was blindly extracting `err.response?.data?.detail` and rendering it into a persistent red banner. When axios received a non-JSON body (Cloudflare 520 HTML, nginx 502 HTML, etc.), the raw HTML markup itself would leak into the UI as the error message — making a *transient* server hiccup look like a *permanent* failure.
- **Fix**: Rewrote error handler to only trust structured JSON with a string `detail` field. HTML payloads are ignored. Every HTTP code gets a friendly message:
  - 401/403 → "Email or password is incorrect. Please try again."
  - 502/503/504/520/521/522/523/524 → "Server is momentarily unavailable — please retry in 10 seconds."
  - Network Error → "Cannot reach the server. Check your internet or try again."
  - Anything else → "Login failed (code XXX). Please try again."
- Files touched: `/app/frontend/src/pages/UniversalLogin.js`.
- Verified in preview: submitting a bad password now shows "No account found with this email" cleanly. Raw HTML from any upstream error will never render in the banner again.
- **User action needed**: Redeploy production so the new bundle ships. Existing users may need to hard-refresh or clear cache once — after that, any future Cloudflare hiccup shows a friendly "please retry" message instead of the scary origin-server-not-parsed text.
